# 实现与测试计划

## P0 产品承诺

单人、单手机、纯侧面机位、保加利亚分腿蹲。反馈对象是“当前完整动作次数”，不是单帧姿势。只有在动作阶段明确、必需关键点可信且问题证据越过语音阈值时才播报；不确定结果只进入总结或直接抑制。

## 已落地架构

```
AVCaptureSession
  → Latest-frame gate
  → Apple Vision / MediaPipe adapter
  → PoseObservation
  → MotionPreprocessor（尺度归一化 + 平滑 + 角度/速度）
  → WorkoutSessionEngine（阶段 → 完整计次 → 问题 → 置信度）
  → SwiftUI / AVSpeechSynthesizer / SwiftData
```

核心计算位于独立 `FormCoachCore` Swift package，不依赖 UI 或摄像头，可用合成关键点确定性测试。感知层以协议隔离，后续替换 MediaPipe、3D 模型或录制视频读取器时无需改判定引擎。

## 实施顺序

1. 工具链升级并启用 MediaPipe；保持 Vision 作为可诊断后备。
2. 将校准页接入相机，以起始位和三次完整动作生成 `CalibrationRepSample`，失败时要求重试而不是静默使用默认值。
3. 建立数据采集工具：原视频、姿态点、规则版本、设备、机位、教练标签分开保存。
4. 先冻结阶段/计次，再调每类问题阈值；训练集与验证集按人员拆分，禁止同一人的片段跨集合。
5. 达到质量门槛后，完成真机稳定性、隐私、可访问性和 TestFlight 验收。

## 自动化测试矩阵

### 已执行

- 校准只接受恰好三次样本并取中位数。
- 三次差异过大时拒绝校准。
- 完整下降—底部—上升—锁定只计一次。
- 半程移动不计次。
- 低置信度问题不触发语音事件。
- 必需点为预测值时问题被抑制。
- 同类语音在冷却窗口内不重复。
- Swift package 全量测试和 iOS target 编译由 `Scripts/verify.sh` 执行。

### 升级工具链/接入真机后

- UI：首次启动权限允许/拒绝、前后台切换、来电/音频中断、训练退出和历史删除。
- 相机：逆光、遮挡、出框、镜像、旋转、多人入镜、设备过热和长时间运行。
- 性能：姿态推理 P50 ≤ 35 ms、P95 ≤ 60 ms；反馈从动作证据完成到声音开始 P95 ≤ 500 ms；连续 20 分钟无队列增长。
- 准确率：完整计次 F1 ≥ 0.95；每类问题在教练共识标签上 precision ≥ 0.85；误语音率 ≤ 每 10 次动作 1 次。
- 隐私：默认无视频文件；删除摘要同时删除关联媒体；断网时核心训练完整可用。

## 人工验证数据设计

每个目标问题至少 10 人、每人 3 个机位质量档、正确与错误各 20 次。两位持证教练独立标注；分歧由第三人裁决。报告必须按设备、身高体型、服装遮挡和训练经验分层，不能只给总准确率。

## 发布闸门

- 所有自动测试通过，Release 构建可归档且无高优先级警告。
- 真机性能与准确率达到上述门槛。
- 每条语音能追溯到 rep、phase、阈值、证据值、模型/规则版本。
- 无网络权限也能完成核心流程；视频保存始终为显式 opt-in。
- TestFlight 至少完成一轮内部和一轮外部测试，崩溃与错误语音回归清零后再送审。

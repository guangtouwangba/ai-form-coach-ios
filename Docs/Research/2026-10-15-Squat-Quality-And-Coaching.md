# 徒手深蹲动作评价与调整建议调研

调研日期：2026-10-15。本文是方案与证据审查，不表示纠错功能已实现。未操作或安装 iPhone，继续遵守用户等待通知的要求。

## 1. 结论与已核实的项目状态

建议采用“端侧姿态模型 + 动作时序特征 + 可解释的分项规则 + 经标注验证的提示策略”。将来有足够标签再增加轻量时序分类器。MediaPipe 输出身体位置，不提供一个已验证的深蹲合格判定器。单台侧面手机应先覆盖明确目标下的幅度、节奏和起止完整性，逐步验证躯干协调及足部线索。

本次直接核对源码：

- `Sources/FormCoachCore/SquatSession.swift:245` 的深蹲 `RepSummary.issues` 明确为空。目前记录髋下降幅度、下降时间和整体躯干变化，核心功能是计次。
- `Sources/FormCoachCore/WorkoutSessionEngine.swift:121` 的旧分腿蹲规则包含躯干变化、幅度和下降速度，但不是已经验证的徒手深蹲标准。尤其站立到下蹲的自然前倾不能直接等于“塌腰”。
- 深蹲计次机要求达到自己的最小周期幅度；浅蹲返回起点时只发消息而不生成 RepSummary。因此动作评价不能只遍历已计入的完整次数，否则恰好漏掉最需要解释的未完成尝试。
- 现有 MediaPipe 适配器读取图像 landmarks；其 z 不是 worldLandmarks 的米制 z。即便新增 worldLandmarks，也仍须单独验证，不把估计的三维坐标视为力学测量。[S1]

## 2. “标准”应如何定义

把三个问题分开：是否看清、是否符合本次训练目标、是否出现已验证的可观察偏离。

静态站稳只能校准起点、人体尺度与噪声，不能确定合适的下蹲目标。用户三次动作很一致，也不能循环证明三次都是标准。若采用动态参考，应由清楚的训练协议或教练确认其适用性；普通用户可继续直接计次，不增加必须完成三次的复杂入口。

不应加入以下简单规则：

- “膝盖超过脚尖就是错误”。Fry 等在特定负重深蹲实验中发现，限制膝前移会改变髋膝力矩分配，不能支持这个通用禁令。该研究样本与负重条件有限，也不能反过来证明每个人任何前移都合适。[S3]
- “躯干越直越标准”。另一项双腿深蹲实验表明躯干和胫骨角度与髋膝力矩分配有关；角度应放在训练目标中解释。[S4]
- “肩髋连线角度变大就是腰椎弯曲”。整体躯干方向不是脊柱曲率，现有关键点不足以做这个等价推断。这是当前测量结构的限制。
- “总分高就安全”。目前没有支持本项目输出伤害风险、安全认证或肌肉发力百分比的验证。

## 3. 按视角决定哪些项目可以评价

下表是本项目的工程范围建议，不是已经测得的准确率。二维角度随视角变化，这是 Google 官方示例明确指出的限制。[S2]

| 项目 | 单台侧面可观察的证据 | 建议输出与优先级 |
|---|---|---|
| 幅度相对目标偏小 | 髋相对下降、膝角变化、底部可见性 | 首版；必须先有明确的目标或已确认参考。不直接套固定膝90°/统一蹲到底 |
| 未回到起始位置 | 稳定起点与回程轨迹 | 首版；输出“尚未回到本次起点”，不称必须过伸锁死膝盖 |
| 下降节奏偏离 | 源时间戳上的下降持续时间 | 首版；只有设定节奏训练目标时才称偏离。自由节奏时只报告快慢变化 |
| 躯干/髋起身协调变化 | 相同动作阶段和深度下的肩髋轨迹、倾角曲线 | 第二步候选；先离线标注验证，称“前倾增加/起身协调变化”，不称腰椎损伤 |
| 脚跟疑似离地 | 高质量 heel/footIndex、足部线段变化、稳定地面/机位 | 实验项；脚部小且遮挡、鞋型与透视会干扰。关键点不能测足底压力，不优先上线 |
| 双膝向内、左右偏移 | 更适合正面且两腿可见的投影 | 后续独立正面检查模式；当前侧面模式不判。投影也不等于真实三维关节受力 |
| 圆背/骨盆卷曲、核心发力、足底重心 | 当前肩髋骨架没有充分证据 | 暂不判断，也不据此诊断原因 |

显示状态应是“本次所检查项目未发现明显偏离 / 有一项可调整 / 证据不足”，附上实际检查范围，而不是笼统盖章“标准”。

## 4. 建议的判断管线

```text
相机/回放 → 真实关键点、原始时间戳
           → 按评价项目分别检查关键点质量、视角、时间覆盖
           → 时间相关滤波、尺度归一化、运动阶段切分
           → 记录每次尝试（包括未完成尝试）及整段特征
           → 目标规则 / 同阶段参考 / 可选时序模型
           → 可解释证据与不确定性策略
           → 一条调整提示 → 下一次动作验证是否改善
```

项目分别门控：脚部未看清可以停用脚跟判断，但在髋膝仍可靠时保留幅度评价。下降/底部/上升任一关键区间缺失，就不拼接出质量结论。单帧越线先记候选；要求跨时间的支持，使用进入/退出不同阈值与测量误差灰区。跨次反复出现可提高提示优先级，但不是所有问题都必须等多次才提示。

参考与容差：采用等尺度像素或已声明的坐标系；不要把归一化 x/y 直接混算角度。比较躯干时按相位或近似相同膝屈曲/深度对齐，避免站立对比底部造成必然假阳性。阈值由人工标注与留出集确定，不拿一个人的站立抖动估计替代动态测量误差。当前关键点分数和手写乘积不是经过校准的“纠错正确概率”。

建议新增以下契约（名称为方案）：

- `SquatAttempt`：每次尝试的起止、完成/未完成原因、阶段轨迹、质量覆盖率；完整计次仍单独保存。
- `SquatQualityProfile`：训练目标、适用视角、可用分析项、目标来源、可选动态参考、规则/模型版本。不要将其混入静态站立检测器。
- `QualityFinding`：具体类型、时间段、观察值、参考范围、支持帧/覆盖率、评价状态、反证/拒绝原因。
- `CoachingCue`：基于哪条 finding、提示原文、触发时间、冷却、下一次待观察的改善指标。

## 5. 从发现变成建议

先说观察到什么，再给一个可执行动作，最后用下一次结果验证。以下为产品文案示例，不是本次真实测试结果：

| 观察 | 一条提示 | 下一次如何检查 |
|---|---|---|
| 两次底部幅度都低于用户已确认的目标，画面可靠 | “这两次比目标浅一些；下一次在舒适范围内接近目标位置。” | 幅度是否进入目标范围，观察是否仍完整 |
| 设定慢速下降练习，但下降时间明显短于目标 | “下一次跟着节拍慢慢下降。” | 源时间戳测到的下降时间，而不是骨架抖动速度 |
| 同深度上升时，髋先抬起且躯干前倾增大，经标注验证 | “下一次放慢起身，让胸口和髋部一起升起。” | 同阶段肩髋时序与躯干曲线是否改善 |
| 膝或脚没有看清 | “膝部没有看清，调整机位后再试。” | 恢复可观测性；不冒充动作纠正 |

不要从观察直接跳到病因：“脚跟疑似抬起”不能自动变成“踝活动度不足”，更不能自动安排康复方案。建议库可由教练审核，先用固定模板，记录适用条件。用户报告疼痛时进入停止本次训练的处理，不继续自动推动幅度。

实时提示与组后复盘分工：实时只显示/播报当前最重要的一条，设置冷却并避免重复打断；组后用带时间定位的短片和证据解释。声音不能要求用户盯着屏幕完成动作。反馈形式有研究支持，但现有抗阻训练综述主要研究表现与适应，不能推出本 App 某种播报频率必然改善动作或降低伤害。[S6]

## 6. 要不要再训练端侧模型

| 路线 | 本项目用途 | 前提与取舍 |
|---|---|---|
| 可解释规则 + 目标/个人相对变化 | 现在的首选 | 特征可观测、目标明确、可标注验证；成本最低，能定位误报 |
| 简单分类器或轻量 TCN/GRU 时序多标签模型 | 标签积累后，补充整体协调等难写规则的模式 | 输入含角度、相对位置、时间与质量掩码；需要跨人验证、不确定时拒答；不应每帧独立二分类 |
| 原始视频表征/多模态模型 | 研发中的离线复核或报告候选 | 算力、标签和推理稳定性成本更高；不会自动解决标准定义，不作为当前逐帧主链 |

Google 的 kNN 示例可参考特征归一化、状态和样本覆盖，但“识别蹲下/站起”不是“评价对错”。不可为了分类消除全部躯干旋转，又期待用同一表征判断前倾。[S2]

Fitness-AQA 的 ECCV 2022 工作使用专家标注训练动作错误识别，覆盖 BackSquat、BarbellRow、OverheadPress；其方法与标签设计有参考价值，但负重背蹲不是本项目徒手深蹲。作者仓库明确数据只可非商业用途，因此不直接纳入产品训练资产或商用模型权重。[S5]

KIMORE 提供医生定义特征及临床评分，但任务、RGB-D 传感器与康复人群不同，只作为评价方法参考，不借用它的分数证明手机健身纠错有效。[S7]

找到的 2025 IEEE Access 深蹲纠错论文使用立体相机、MediaPipe 与 Bi-CGRU，并报告较高结果；输入配置并非本项目单目 iPhone，不能将论文数字写成本 App 的准确率。[S8]

## 7. 单人开发怎样验证

1. 先用自己的本地录像验证可重放、可解释、改变一个变量时发现能否相应改变。不同幅度、已设不同节奏、未回起点、遮挡、出框、机位移动都需要正反例；不必冒险故意做极端错误动作。
2. 建立人工复核表：视频/人物/源片ID、目标、视角、每次起止、各项“符合/偏离/看不清”、证据时段和可用提示。最好由两名教练独立评，再处理分歧；第一步找一名教练审查少量样本比堆无标签视频更有用。
3. 本人的视频只能证明本人场景；扩展到不同身材、衣服、机位与环境。按人物和原始视频分训练/验证/测试，屏拍版和原片归同组，同周期复制不得跨集合。
4. 当前“五次正例”是一个真实周期复制五次，只能验证管线与计数；不能变成五份独立质量标签。模拟关键点只测算法逻辑，拍屏测试主要测识别域变化，都不能独自证明动作标准。
5. 分别报告测量误差、每项提示 precision/recall、正确动作每分钟误报、评价覆盖率与拒答率、时延。避免只报整体 accuracy，也不能靠几乎全部拒答刷高 precision。
6. 可先设高 precision 的内部上线目标，但目标必须带样本数与置信区间，不等于已有结果。超出已验证人群/机位时显示能力范围，遇到新失败片归档回归。
7. 真正验证“建议有效”：除了识别对错，还要复核提示是否恰当、用户能否理解、后续动作是否在同条件下改善；两模型同意不等于教练真值，也不由一次改善推出因果。

建议开发顺序：先离线回放的幅度/节奏/起止分项证据与未完成尝试，再做组后提示和下一次变化对照，验证后才开启实时播报。躯干协调作为下一项研究，脚跟和正面膝对齐单独排期。首版先不输出未经验证的100分总评。

## 实现

- 通过 Google 官方 Swift Package 链接真正的 `MediaPipeTasksVision` 1.1.1，固定 `7dd8fe00c17e7732818ea1406c4fb64beb237e6c`；默认使用 Full 模型。官方入口：[iOS 指南](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/ios)、[源码](https://github.com/google-ai-edge/mediapipe)。不用旧 Pod/编译开关，不用模拟关键点冒充模型输出。
- Full 模型沿用仓库文件，SHA-256 `4eaa5eb7a98365221087693fcc286334cf0858e2eb6e15b506aa4a7ecdcec4ad`。
- 串行后台 `.video` 推理，使用源时间戳，实时相机至多一帧在途，不积压。保留 Apple Vision 切换对照。主动切换会重新建立站稳基线；当前组/录像期间不能切换。
- 标准化为转正图像、左上原点。MediaPipe 的旋转元数据路径曾输出不符合该约定的坐标；修复为先转正像素再推理，保留旋转实片回归。相机已输出竖屏像素，走无额外旋转的路径。
- 真实关键点骨架：绿色强证据、橙色弱证据，与预览使用相同 aspect-fill 裁切。骨架显示不等于动作质量合格。
- 区分未找到人、多人、具体关节缺失/低置信度、出画、人物过小、几何异常、姿势未站直、机位、晃动、帧间断、相机/骨架改变等。不能由低置信度直接断言是对焦或光线问题。
- 站稳仍要求两秒连续时间、足够样本、可靠可见链条、姿态几何与尺度/关节抖动检查。保持模型各自的置信度策略，没有为此片统一降低阈值。计次要求回到起点、完整起落与防抖，缺帧/丢人不补计。
- 诊断页主动录制约 20 秒无声相机视频，并保存真实输入关键点；默认不录像。文件留在本机 `Documents/PoseDiagnostics`，通过“文件”管理或手动导出。关键点时间相对首个姿态帧，不声称与录像起始逐帧精确同步；对照推理以同一视频的时间轴为准。
- 同一视频依次跑两个模型，导出实际引擎版本、帧数、可用姿态帧、首次站稳时间、计次、耗时、最大源采样间隔和拒绝原因。一个引擎失败会单独记录，不伪造零次成功结果。回放不写训练历史，关闭清理导入副本，原诊断录像和导出报告保留。

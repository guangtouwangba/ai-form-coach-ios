# 徒手深蹲观察与节奏反馈：实现及验证

2026-10-16。本轮实现了计划中的动作观察基础、事实反馈和 App 接入；没有把单人 OfficeSquat 实验权重包装成通用动作教练，没有安装或启动 iPhone App。

## 已实现

- 独立的动作尝试记录：完整周期计次之外，小幅往返和已确认开始后发生的暂停、跟踪中断、机位变化、录像截断、超时均可保留。短促抖动不自动成为动作尝试。
- 起止、最低点、下降/回起时长、归一化髋部下降、投影膝角及各阶段采样数；使用真实输入时间戳。
- 逐项输出达到目标、未达到目标、不可判断、未配置目标。下降节奏支持用户选择至少 1/2/3 秒；默认不设置目标，只记录。幅度目标仅在代码接口支持带来源的显式参考，界面没有提供未经审核的统一深度标准。
- 中断后不拼接半次动作，不用推测补足丢失的最低点或回起。当前采用保守策略：必需观察失败即终止本次评价窗口，已计次记录仍保留。
- 组后只优先显示一条有证据的建议；逐次展开可查看测量、目标和不可判断原因。本版没有自动实时纠错播报。
- 录像回放可定位最低点；没有关联录像的现场训练只展示时间与测量，明确说明不能视频回看。
- 目标、动作尝试及证据写入草稿和训练历史；旧总结没有新字段仍可解码，旧记录缺质量评价时不会被解释为动作标准。
- 修复手动操作发现的界面问题：有动作尝试但零计次时不再笼统责怪机位；历史各组展示尝试数；零计次不提供空的周期详情按钮；会话返回不再绕回上一组。

## 算法选择与实际修复

完整周期计次的幅度、关节角和站稳阈值没有为了测试片段降低。动作尝试使用独立、更小的运动启用条件，并要求持续运动及髋/膝同时变化；它只记录观察，不把小幅动作自动认定为技术错误。

真实 10Hz 回放曾暴露：第一次确认回起后，尝试记录器重新要求一段站稳，后续连续动作虽然计次成功却没有记录。修复为确认回起后直接准备记录下一次，只有跟踪失败、暂停等中断才要求重新回到起点。新增真实骨架回归固定检查 5 个计次对应 5 条尝试、关联 ID 为 1–5。

时间戳断档原来会中断内部状态但可能没有输出具体原因；现在显式报告 frameGap，并保留受影响尝试。停止输入的超时路径也会同步保存中断记录。

## 可复现验证

核心：`swift test`。本轮新增的小幅运动、连续真实动作、节奏目标、遮挡、暂停、录像结束、断档、机位变化、目标冻结和兼容测试均在仓库中。

Mac 真实视频 → Python MediaPipe → 同一 Swift 核心：

```sh
COACH_POSE_PYTHON=/tmp/coach-alternatives-venv/bin/python \
  bash Scripts/verify-squat-quality.sh
```

从项目根目录运行。上述隔离环境是本机现有的 MediaPipe 1.1.1 / OpenCV 5.0.0 环境，不保证 /tmp 在重启后仍存在；恢复环境时沿用[既有依赖快照](../OnDevice-Model-Comparison-2026-10-16/evidence/python-packages.txt)。脚本不安装依赖、不运行设备安装命令。

导出器校验与 App 相同的姿态资产 SHA，顺序解码，不按 AVI 声明末帧随机寻帧。导出附源片与模型 SHA、实际帧数、采样数、方向策略及时间戳回退次数。本轮侧面片段实际解码 630 帧、10Hz 采样 210 帧，时间戳回退 0 次。

[批量结果](results/mac-regression-summary.json)、[同一骨架的 Swift 结果](results/mac-shared-core.json)、[骨架输入及来源](results/real-mediapipe-poses.json)。节奏回归显式选择 2 秒目标，素材下降短于此目标；这不是在给该视频下“姿势不标准”的结论。

**样本边界：**五次正例是既有的同一个真实周期重复并加入开头静止段，用于连续处理回归，不是五个独立的人体动作或自然站稳样本。原片和旋转版也是同一来源，不算独立人物。以上结果不证明多人质量识别率。

## 模拟器验证方式

使用现有 iPhone 17 Pro Max / iOS 26.5 模拟器、AIFormCoach-Integration scheme，禁用签名，仅选择 iOS Simulator destination。

1. 自动集成测试：导入、取消、实际视频解码、真实 MediaPipe 推理、模型对比、草稿恢复、训练总结、保存及重开历史。
2. 增加 Mac 与模拟器一致性测试：同一 210 帧真实 MediaPipe 输入，在模拟器运行同一 Swift 核心，与 Mac 输出比较逐次时间边界、计次关联、测量、覆盖及评价；随机记录 UUID 不作为算法比较项。
3. 真实 MediaPipe 视频推理另测 30Hz 输入、HD、旋转及反例；与 10Hz 回放分别报告，不宣称两次骨架估计数值完全一致。
4. 手动 UI 检查使用已有 opt-in 临时数据库测试窗口，黄色“模拟姿态输入”标记始终显示；只有相机输入为合成数据，设置、按钮、Swift 核心、总结和存储是实际实现。该检查不冒充真人识别准确率测试。

结果：**42 项 Swift 核心测试通过；模拟器完整集成套件 32 项中，26 项通过、6 项跳过、0 失败。** 六项跳过包括五项真机专属测试与一项需要单独开启的手动窗口；手动窗口随后单独开启并实际操作。最低点暂停定位及回放页关闭的最后改动，另跑对应两项集成回归，2/2 通过。

设备专属测试保持跳过，未以模拟器证明 iPhone 相机性能、发热或拍屏可靠性。

## 尚未完成的能力

本版是事实观察及选定任务目标反馈，不是通用深蹲质量判定模型。多人侧面数据、独立教练标注、逐问题模型训练与人物隔离盲测仍需推进；[标注表模板](annotation-template.csv)已创建。膝内扣、腰背形态、足跟离地和伤害风险没有新增判断。

阶段采样数是保守的连续有效窗口统计；尚未实现逐关节置信度校准或对关键点缺失的恢复评价。下降起止和投影几何是采样估计，不是实验室运动捕捉真值。没有量化整段录像的专家测量误差，也没有完成多人误报/漏报验收。

下一步是收集新人物真实侧面录像，冻结标签和分组后训练逐问题小模型，评估精度、召回、可评价覆盖及不确定性；真机安装与回归继续等待用户通知。

# 页面布局与信息层级优化 · 2026-10-15

本轮直接优化原生 SwiftUI 页面，重点为首页、相机页、训练总结。沿用上一轮已修正的新建/恢复、返回和保存规则。

## 阅读与操作顺序

| 页面 | 原先的主要问题 | 现在的层级 |
|---|---|---|
| 首页 | 动作、说明、多个白卡片容易同等显眼；有草稿时新建仍优先 | 有草稿先显示深色继续卡和已保留次数；无草稿突出新训练。机位帮助、最近训练、隐私说明依次降低权重 |
| 相机 | 中央大进度环、长文字和上下堆叠大按钮占用预览 | 顶部显示组别与训练腿；左上角计数；中间让给预览；底部只保留当前提示和相关操作。训练时结束/暂停并排，说明变成次级链接 |
| 总结 | 多条问题卡和逐次列表展开，占用首屏 | 先看完整次数及带提示的动作数，再看下一组重点；全部提示与逐次证据按需展开；下一组/保存始终固定底部 |
| 保存完成 | 标题、完成提示、说明重复 | 完成标识、两组总次数摘要、查看记录/返回首页 |

采用现有绿色与琥珀色体系。深色区域的主要操作使用琥珀色，浅色页面使用深绿；数字、提示、说明分别使用清晰的字号层级。没有增加分数、合格率或未经验证的“稳定动作”结论。

总结的两项指标刻意分开：**完整动作数**是已记录次数；**带提示的动作数**按动作去重，不是问题条数。展开区另外展示提示条数。历史总结读取保存记录中的训练腿、目标和组别。

## 状态显示修复

原生走查发现相机从判断暂停或暂停菜单返回后，部分控件可能显示不完整。本轮取消相机页面的进出/隐式动画，按状态重建上层控件，保留独立底层预览；最新截图 08 已确认计数、状态、语音、结束和暂停控件都可见。

另外修复了从低质量状态暂停再返回时过早显示“训练中”的问题：有效输入恢复前继续显示“判断已暂停”。新增回归覆盖这条路径，并补充暂停/恢复前后仍是同一个预览对象的断言。

## 实际走查

在 Mac 的 iPhone 17 Pro Max / iOS 26.5 Simulator 操作原生 App，最终走过：

1. 首页 → 新训练 → 设置 → 相机 → 三次校准 → 第一组。
2. 注入低质量姿态 → 判断暂停 → 手动暂停 → 返回仍显示判断暂停 → 输入恢复后自动继续。
3. 稍后继续回首页 → 查看优先显示的草稿卡 → 恢复机位 → 继续本组 → 总结。
4. 展开全部提示与逐次证据 → 查看单次记录 → 返回总结 → 再做一组。
5. 第二组 → 结束确认 → 总结 → 保存 → 打开第二组历史总结 → 返回历史及首页。

最终测试会话为两组 **5 / 9 次，共 14 次**。这些是生产引擎处理模拟姿态输入的流程证据，不代表真人动作准确性。交互窗口使用独立临时数据，带黄色“模拟姿态输入”标识；普通 App 未加入模拟计数功能。模拟器相机区域没有真实摄像头画面。

同色实底设计 token 的计算对比度：普通次级文字/页面背景约 4.76:1，深色卡片次级文字约 7.88:1，琥珀色按钮文字约 6.77:1。实时视频背景并非固定色，这些计算不等同于整屏可访问性认证。主要按钮最小高度 52pt，图标与说明操作最小高度 44pt。

本轮验证重点为接近用户 iPhone 尺寸的 Pro Max 布局、真实相机存活和流程。没有声称完成小屏、全部辅助字号、VoiceOver 或所有触摸手势的全面验收。
